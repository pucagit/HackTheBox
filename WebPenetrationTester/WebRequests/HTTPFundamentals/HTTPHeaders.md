# HTTP Headers
## General Headers
General headers are used in both HTTP requests and responses. They are contextual and are used to describe the message rather than its contents.

<table class="bg-neutral-800 text-primary w-full"><thead class="text-left rounded-t-lg"><tr class="border-t-neutral-600 first:border-t-0 border-t"><th class="bg-neutral-700 first:rounded-tl-lg last:rounded-tr-lg p-4"><strong class="font-bold">Header</strong></th><th class="bg-neutral-700 first:rounded-tl-lg last:rounded-tr-lg p-4"><strong class="font-bold">Example</strong></th><th class="bg-neutral-700 first:rounded-tl-lg last:rounded-tr-lg p-4"><strong class="font-bold">Description</strong></th></tr></thead><tbody class="font-mono text-sm"><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Date</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Date: Wed, 16 Feb 2022 10:38:44 GMT</code></td><td class="p-4">Holds the date and time at which the message originated. It's preferred to convert the time to the standard <a href="https://en.wikipedia.org/wiki/Coordinated_Universal_Time" rel="nofollow" target="_blank" class="hover:underline text-green-400">UTC</a> time zone.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Connection</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Connection: close</code></td><td class="p-4">Dictates if the current network connection should stay alive after the request finishes. Two commonly used values for this header are <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">close</code> and <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">keep-alive</code>. The <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">close</code> value from either the client or server means that they would like to terminate the connection, while the <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">keep-alive</code> header indicates that the connection should remain open to receive more data and input.</td></tr></tbody></table>

## Entity Headers
Similar to general headers, Entity Headers can be common to both the request and response. These headers are used to describe the content (entity) transferred by a message. They are usually found in responses and POST or PUT requests.

<table class="bg-neutral-800 text-primary w-full"><thead class="text-left rounded-t-lg"><tr class="border-t-neutral-600 first:border-t-0 border-t"><th class="bg-neutral-700 first:rounded-tl-lg last:rounded-tr-lg p-4"><strong class="font-bold">Header</strong></th><th class="bg-neutral-700 first:rounded-tl-lg last:rounded-tr-lg p-4"><strong class="font-bold">Example</strong></th><th class="bg-neutral-700 first:rounded-tl-lg last:rounded-tr-lg p-4"><strong class="font-bold">Description</strong></th></tr></thead><tbody class="font-mono text-sm"><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Content-Type</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Content-Type: text/html</code></td><td class="p-4">Used to describe the type of resource being transferred. The value is automatically added by the browsers on the client-side and returned in the server response. The <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">charset</code> field denotes the encoding standard, such as <a href="https://en.wikipedia.org/wiki/UTF-8" rel="nofollow" target="_blank" class="hover:underline text-green-400">UTF-8</a>.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Media-Type</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Media-Type: application/pdf</code></td><td class="p-4">The <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">media-type</code> is similar to <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Content-Type</code>, and describes the data being transferred. This header can play a crucial role in making the server interpret our input. The <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">charset</code> field may also be used with this header.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Boundary</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">boundary="b4e4fbd93540"</code></td><td class="p-4">Acts as a marker to separate content when there is more than one in the same message. For example, within a form data, this boundary gets used as <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">--b4e4fbd93540</code> to separate different parts of the form.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Content-Length</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Content-Length: 385</code></td><td class="p-4">Holds the size of the entity being passed. This header is necessary as the server uses it to read data from the message body, and is automatically generated by the browser and tools like cURL.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Content-Encoding</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Content-Encoding: gzip</code></td><td class="p-4">Data can undergo multiple transformations before being passed. For example, large amounts of data can be compressed to reduce the message size. The type of encoding being used should be specified using the <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Content-Encoding</code> header.</td></tr></tbody></table>

## Request Headers
The client sends Request Headers in an HTTP transaction. These headers are used in an HTTP request and do not relate to the content of the message. The following headers are commonly seen in HTTP requests.

<table class="bg-neutral-800 text-primary w-full"><thead class="text-left rounded-t-lg"><tr class="border-t-neutral-600 first:border-t-0 border-t"><th class="bg-neutral-700 first:rounded-tl-lg last:rounded-tr-lg p-4"><strong class="font-bold">Header</strong></th><th class="bg-neutral-700 first:rounded-tl-lg last:rounded-tr-lg p-4"><strong class="font-bold">Example</strong></th><th class="bg-neutral-700 first:rounded-tl-lg last:rounded-tr-lg p-4"><strong class="font-bold">Description</strong></th></tr></thead><tbody class="font-mono text-sm"><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Host</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Host: www.inlanefreight.com</code></td><td class="p-4">Used to specify the host being queried for the resource. This can be a domain name or an IP address. HTTP servers can be configured to host different websites, which are revealed based on the hostname. This makes the host header an important enumeration target, as it can indicate the existence of other hosts on the target server.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">User-Agent</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">User-Agent: curl/7.77.0</code></td><td class="p-4">The <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">User-Agent</code> header is used to describe the client requesting resources. This header can reveal a lot about the client, such as the browser, its version, and the operating system.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Referer</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Referer: http://www.inlanefreight.com/</code></td><td class="p-4">Denotes where the current request is coming from. For example, clicking a link from Google search results would make <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">https://google.com</code> the referer. Trusting this header can be dangerous as it can be easily manipulated, leading to unintended consequences.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Accept</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Accept: */*</code></td><td class="p-4">The <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Accept</code> header describes which media types the client can understand. It can contain multiple media types separated by commas. The <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">*/*</code> value signifies that all media types are accepted.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Cookie</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Cookie: PHPSESSID=b4e4fbd93540</code></td><td class="p-4">Contains cookie-value pairs in the format <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">name=value</code>. A <a href="https://en.wikipedia.org/wiki/HTTP_cookie" rel="nofollow" target="_blank" class="hover:underline text-green-400">cookie</a> is a piece of data stored on the client-side and on the server, which acts as an identifier. These are passed to the server per request, thus maintaining the client's access. Cookies can also serve other purposes, such as saving user preferences or session tracking. There can be multiple cookies in a single header separated by a semi-colon.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Authorization</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Authorization: BASIC cGFzc3dvcmQK</code></td><td class="p-4">Another method for the server to identify clients. After successful authentication, the server returns a token unique to the client. Unlike cookies, tokens are stored only on the client-side and retrieved by the server per request. There are multiple types of authentication types based on the webserver and application type used.</td></tr></tbody></table>

## Response Headers
Response Headers can be used in an HTTP response and do not relate to the content. Certain response headers such as Age, Location, and Server are used to provide more context about the response. The following headers are commonly seen in HTTP responses.

It can be used to gain information about the server, such as its version, and enumerate it further.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Set-Cookie</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Set-Cookie: PHPSESSID=b4e4fbd93540</code></td><td class="p-4">Contains the cookies needed for client identification. ## Security Headers
Finally, we have Security Headers. With the increase in the variety of browsers and web-based attacks, defining certain headers that enhanced security was necessary. HTTP Security headers are a class of response headers used to specify certain rules and policies to be followed by the browser while accessing the website.

<table class="bg-neutral-800 text-primary w-full"><thead class="text-left rounded-t-lg"><tr class="border-t-neutral-600 first:border-t-0 border-t"><th class="bg-neutral-700 first:rounded-tl-lg last:rounded-tr-lg p-4"><strong class="font-bold">Header</strong></th><th class="bg-neutral-700 first:rounded-tl-lg last:rounded-tr-lg p-4"><strong class="font-bold">Example</strong></th><th class="bg-neutral-700 first:rounded-tl-lg last:rounded-tr-lg p-4"><strong class="font-bold">Description</strong></th></tr></thead><tbody class="font-mono text-sm"><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Content-Security-Policy</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Content-Security-Policy: script-src 'self'</code></td><td class="p-4">Dictates the website's policy towards externally injected resources. This could be JavaScript code as well as script resources. This header instructs the browser to accept resources only from certain trusted domains, hence preventing attacks such as <a href="https://en.wikipedia.org/wiki/Cross-site_scripting" rel="nofollow" target="_blank" class="hover:underline text-green-400">Cross-site scripting (XSS)</a>.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Strict-Transport-Security</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Strict-Transport-Security: max-age=31536000</code></td><td class="p-4">Prevents the browser from accessing the website over the plaintext HTTP protocol, and forces all communication to be carried over the secure HTTPS protocol. This prevents attackers from sniffing web traffic and accessing protected information such as passwords or other sensitive data.</td></tr><tr class="border-t-neutral-600 first:border-t-0 border-t"><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Referrer-Policy</code></td><td class="p-4"><code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Referrer-Policy: origin</code></td><td class="p-4">Dictates whether the browser should include the value specified via the <code dir="ltr" class="bg-neutral-700 mb-6 text-blue-250 py-1 px-1.5">Referer</code> header or not. It can help in avoiding disclosing sensitive URLs and information while browsing the website.</td></tr></tbody></table>
